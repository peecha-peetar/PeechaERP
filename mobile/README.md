# اپِ موبایلِ پیچا — پخشِ سرد/گرم

کلاینتِ React Native برایِ `peecha_api` (مسیرِ سرور: `src/peecha_api/`). طبقِ تصمیمِ کاربر: بدونِ Flutter، آفلاین-اول، رویِ همان حساب‌کاربریِ ERP.

از R187 به بعد این پروژه زیرِ **Expo** اجرا می‌شود (نه بیلدِ نیتیوِ خامِ React Native CLI) — چون سندباکسِ توسعه‌یِ فعلی نه Android SDK دارد نه Xcode، اما با Expo Go (اپِ رایگانِ روی گوشی) بدونِ هیچ بیلدِ نیتیوی روی گوشیِ واقعی اجرا می‌شود.

## اجرا رویِ گوشیِ خودتان (سریع‌ترین راه)

۱. یک کامپیوتر (ویندوز/مک/لینوکس، حتی ضعیف) لازم است — فقط برای اجرایِ سرورِ توسعه (Metro)، نه برایِ بیلد.
۲. رویِ همان کامپیوتر: Node.js نصب کنید، سپس:
   ```
   cd mobile
   npm install
   npx expo start
   ```
   (برای اتصال از رویِ شبکه‌یِ دیگر/اینترنت به‌جایِ همان Wi-Fi: `npx expo start --tunnel`)
۳. رویِ گوشی، اپِ **Expo Go** را از Google Play (اندروید) یا App Store (آیفون) نصب کنید.
۴. کیوآرکدِ نمایش‌داده‌شده در ترمینال را با Expo Go اسکن کنید — اپ همان‌جا روی گوشی بالا می‌آید.
۵. در صفحه‌یِ ورود، رویِ «آدرسِ سرور» بزنید و آدرسِ IPِ سرورِ `peecha_api`ِ خودتان را وارد کنید (مثلاً `http://192.168.1.10:8000`؛ نه `localhost` — چون `localhost` رویِ گوشی خودِ گوشی است، نه کامپیوترِ شما). بعد وارد شوید.

نکته: خودِ این سشنِ ابری (Claude) امکانِ برقراریِ تونلِ زنده تا گوشیِ شما را ندارد — تست شد و شبکه‌یِ این سندباکس اتصال به زیرساختِ Android SDK (`dl.google.com`) و به ngrok/تونلِ Expo هردو را مسدود می‌کند. اجرایِ واقعی حتماً باید از یک کامپیوترِ خودتان (بدونِ این محدودیت‌ها) انجام شود.

## ساختِ یک نصبِ مستقلِ APK/IPA (اختیاری، نه لازم برایِ تست)

اگر بعداً خواستید یک فایلِ نصبیِ مستقل (بدونِ نیاز به Expo Go) بسازید، از EAS Build استفاده کنید (نیازمندِ حسابِ رایگانِ Expo):
```
npx eas-cli build --platform android --profile preview
```
این هم باز نیازمندِ یک کامپیوترِ متصل به اینترنتِ آزاد است (نه این سندباکس).

## چه چیزهایی هنوز محدودند

- GPS واقعی (`ExpoLocationProvider`)، عکسِ دوربینِ واقعی و امضایِ دیجیتالِ واقعی (`ExpoCaptureProvider`) از R187/R191 وصل هستند -- در اولین استفاده، Expo Go دسترسیِ موقعیت/دوربین را از کاربر می‌پرسد. امضا از طریقِ `SignaturePadProvider` (یک Modal با کانواسِ لمسی، پُلِ لازم چون CaptureProvider خودش یک کلاسِ ساده بدونِ دسترسی به React است) کار می‌کند.
- ناوبری دستی است (بدونِ `react-navigation`) — طبقِ همان تصمیمِ عمدیِ فازِ اسکلت‌سازی.
- AR Aging («وصولِ عقب‌افتاده» بر اساسِ سررسیدِ فاکتورِ مشخص) پیاده نشده -- نیازمندِ ردیابیِ تخصیصِ پرداخت به فاکتور است که در کدِ فعلی (نه دسکتاپ، نه API) اصلاً وجود ندارد.

## تست‌ها

منطقِ خالص (صف/سینک/کلاینتِ API) با Jest تست می‌شود و به گوشی/شبیه‌ساز نیازی ندارد:
```
npm test
npm run typecheck
```
